Also

Older and smaller frameworks that shaped the twelve, described without a measurement.

These were not built or measured for this site, so they have no number. Each is described from its own documentation or its Wikipedia article.

Remix and React Router

Remix was a React framework with server data loading and nested routes, from the makers of React Router. Its ideas were folded back into React Router 7, which can be used as a framework. Closest here: React.

  • React Router
  • Wikipedia: Remix

Gatsby

A React framework for static sites, by Kyle Mathews, from 2015. It pulled data into pages with GraphQL at build time. Netlify bought the company in 2023. Closest here: Next.js.

  • Wikipedia: Gatsby

Ember

An application framework from 2011 whose rule is convention over configuration: a fixed project layout, a router and a data layer, kept stable across versions for long-lived apps. Closest here: Angular.

  • Ember.js
  • Wikipedia: Ember.js

Alpine.js

Caleb Porzio’s small library from 2019 that adds behaviour with attributes in HTML, in the browser, with no build step. The client-side cousin of htmx’s idea. Closest here: htmx.

  • Alpine.js
  • Wikipedia: Alpine.js

Backbone

Jeremy Ashkenas’s 2010 library that gave browser apps models, views and a router and left the rest alone. It has no data binding: views re-render when you tell them to. Closest here: React.

  • Backbone.js
  • Wikipedia: Backbone.js

jQuery

John Resig’s 2006 library that made selecting and changing DOM nodes the same in every browser. It is not a component framework, and the frameworks on this site mostly exist because pages outgrew it. Closest here: React.

  • jQuery
  • Wikipedia: jQuery
