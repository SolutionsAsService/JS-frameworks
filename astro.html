content-first framework

Astro

Static HTML by default, with islands of interactivity where you ask for them.

  • Kindcontent-first framework
  • Made byFred K. Schott and the Astro team
  • Since2021
  • Written inAstro components, with JavaScript or TypeScript
  • Checked on npmfirst version 2021-03-12, 1.0.0 on 2022-08-09

At a glance

Pros

Content pages with no JavaScript cost. Use the UI library you already know, or several.

Cons

Not made for highly interactive, app-like pages. State shared between islands needs extra care.

What it is

Astro is a framework for sites that are mostly content: blogs, docs, marketing and shops. A page is rendered to plain HTML at build time and no JavaScript is sent unless a component needs it.

It does not have its own component model for interactivity. An interactive piece, called an island, is written in React, Preact, Vue, Svelte, Solid or Lit, and may be mixed on the same page.

How it works

  1. Pages are .astro files that render to HTML at build time
  2. A UI component marked client:* becomes an island
  3. HTML ships; only the islands’ JavaScript ships
  4. Each island hydrates on load, when visible or when idle

A directive such as client:load or client:visible tells Astro when to hydrate an island. The rest of the page stays inert HTML.

Content collections give Markdown and data files a typed schema, and adapters allow server rendering when a page needs it.

Overlaps and differences

Overlaps with

  • Preact: A common choice for the interactive islands.
  • Next.js: Both can emit static HTML for content pages.

Differs from

  • Next.js: Next.js hydrates its whole React tree for a page; Astro hydrates only the islands.
  • Qwik: Both avoid shipping everything up front, by opposite means: Astro by not sending, Qwik by deferring.

What it is good at, and what it costs

Good at

  • Content pages with no JavaScript cost
  • Use the UI library you already know, or several
  • Fast static output

Costs

  • Not made for highly interactive, app-like pages
  • State shared between islands needs extra care
  • Mixing libraries means shipping each one’s runtime
