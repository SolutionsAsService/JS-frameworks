React

Describe the screen as functions of state, and let React work out the changes.

What it is

React describes a screen as a tree of components. A component is a function that takes props and returns what that part of the screen should look like, written in JSX, which looks like HTML inside JavaScript. State lives in hooks such as useState.

React is a library, not a full framework: it draws the UI and leaves routing, data loading and the build to you or to a framework built on it, of which Next.js is the biggest.

How it works

  1. Write components in JSX
  2. A build step turns JSX into function calls
  3. react and react-dom ship to the browser
  4. State changes re-run components; React diffs and patches the DOM

When state changes, React calls the component again and gets a new description of the UI. It compares that tree with the previous one (the virtual DOM, reconciled by an algorithm called Fiber) and changes only the real DOM nodes that differ.

Rendering can be paused, resumed and prioritised, which is what concurrent rendering means. Hooks keep state per component instance, so the order of hook calls must not change between renders.

Server Components are components that run only on the server and send their output to the client, so their code never ships to the browser. They need a framework or bundler that supports them.

Overlaps and differences

Overlaps with

  • Preact: Preact implements the same API in a much smaller package, and preact/compat lets many React libraries run on it.
  • Next.js: Next.js is a framework built on React, and supplies the routing, server rendering and bundling React leaves out.
  • Solid: Solid uses JSX too, so code looks alike, but it does not re-run components.

Differs from

  • Svelte: Svelte moves the work to build time: a compiler writes the DOM updates, with no diffing at run time.
  • Vue: Vue tracks which state each component reads and re-renders only that component, so developers rarely write memoization by hand.

What it is good at, and what it costs

Good at

  • The largest ecosystem and hiring pool of the frameworks here
  • One model for the web and, with React Native, for mobile
  • Very flexible: you pick the router, data layer and build

Costs

  • The runtime ships to every visitor (see the measured figure)
  • You assemble the rest of the stack yourself, or adopt a framework that has
  • Re-running components on every change means unnecessary re-renders are the developer’s to find and prevent
