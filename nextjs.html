React meta-framework

Next.js

React plus the parts React leaves out: routes, servers, bundling and data.

  • KindReact meta-framework
  • Made byVercel (formerly ZEIT)
  • Since2016
  • Written inJavaScript or TypeScript, with React
  • Checked on npm1.0.0 on 2016-10-25 (npm’s 2011 “next” entries are an unrelated package)

At a glance

Pros

One tool for pages, routes, rendering modes and deployment. Search-friendly HTML from the first response.

Cons

It inherits React’s runtime and adds its own (see the measured figure). Several rendering modes and caching layers must be understood to predict behaviour.

What it is

Next.js is a framework built on React. Its router is the file system: a folder becomes a URL, and special files in it (page, layout) say what to draw. It adds server rendering, static generation, API endpoints, image and font handling, and its own bundler.

In the App Router, components are Server Components by default. A file marked 'use client' becomes a Client Component, which is the kind used for state and interaction.

How it works

  1. Folders under app/ become routes
  2. Each route is rendered on the server or at build time
  3. HTML, then the React client code, reach the browser
  4. React hydrates the page and takes over interaction

For each route Next.js decides when its HTML is made: at build time (static), on each request (dynamic), or a mixture with cached results that are refreshed. The server sends HTML first, so the page shows before any JavaScript runs.

The browser then downloads the React runtime and the Client Components on the page, and React hydrates the HTML: it attaches event handlers to the markup already there instead of drawing it again. Layouts stay mounted while the user moves between routes, and Server Actions let a form call a server function directly.

Overlaps and differences

Overlaps with

  • React: Every Next.js component is a React component, and React libraries work in it.
  • Nuxt: Nuxt does for Vue what Next.js does for React: file routing, server rendering, hybrid rendering per route.
  • Astro: Both can produce static HTML for content pages.

Differs from

  • Astro: Astro ships no JavaScript by default and hydrates only chosen islands, where Next.js hydrates the Client Components on a page.
  • Qwik: Qwik resumes where the server stopped instead of hydrating, so it needs no start-up re-run.

What it is good at, and what it costs

Good at

  • One tool for pages, routes, rendering modes and deployment
  • Search-friendly HTML from the first response
  • Big ecosystem, because React’s is its own

Costs

  • It inherits React’s runtime and adds its own (see the measured figure)
  • Several rendering modes and caching layers must be understood to predict behaviour
  • Built around React and, in practice, around one hosting company’s platform
