How the numbers were measured

For each framework, one page: a heading and one button that reads “count: N” and adds one when clicked. It was built with the framework’s production build, using the recommended tooling, then served and opened in a fresh headless Chromium. Every JavaScript response the browser fetched was compressed with gzip at level 9, and the sizes added up. Then the button was clicked once and any further JavaScript was counted too. The click had to change the text from “count: 0” to “count: 1”, or the measurement failed.

The script is tools/measure-sizes.mjs; the sources of the fourteen apps (fifteen measurements: Qwik is measured twice), and the commands to build each, are in tools/. Measured on 2026-11-08 with Node 22.23.4.

What this does not tell you

  • The site’s own JavaScript is one small file. script.js is 492 B gzipped (gzip -9 -n): it only runs the light and dark button, and every page works without it.
  • “Works with” is not measured. The pairs on each scrap (for example Next.js with React and Vercel) come from each project’s own wording about what it builds on or ships with, and are not linked pair by pair.
  • The twelve are the author’s choice. Three are used in the author’s repositories (React, Next.js, Lit), three the author wanted covered (Angular, Vue, Svelte) and six are widely used or take a different road (Nuxt, Solid, Preact, Qwik, Astro, htmx). No ranking or survey chose them, so the set is not the whole field.
  • A counter is not an app. It measures the cost of starting a framework, not how cost grows with features. A framework that is large at the start and small to grow (or the reverse) is hidden here.
  • Bytes are not speed. A small download can still be slow to run, and a larger one can be cached and shared.
  • One run each, one machine. The sizes are deterministic builds, so they repeat; load behaviour such as preloading depends on timing.
  • gzip, not brotli. Servers often send smaller brotli. Checked with brotli at quality 11 (2026-11-08, tools/brotli-check.mjs), the eight static builds (vanilla, solid, preact, lit, svelte, vue, angular, react) keep the same order; the server-rendered builds were not rechecked.
  • Inline script is excluded and printed separately: a framework that moves script into the HTML would otherwise look smaller.
  • Qwik’s default preloads. With its default settings it fetches the click handler while idle, so the click adds nothing; with preloading off the click loads 2.4 kB more. Both are shown on its page.
  • Bundlers changed too. The Vite-based builds use Vite 8, which no longer minifies with esbuild, so a size here may differ from one measured earlier with another bundler.

How the dates were checked

The “Since” year on each page was compared with the npm registry by tools/registry-dates.mjs on 2026-11-08: the first version published, and the dates of 1.0.0, 2.0.0 and 3.0.0. The registry shows when a package was published, not who designed the framework or when its design was first shown, so it corroborates a year and never overrides one. React’s, Next.js’s and Lit’s names were used by unrelated packages before the frameworks took them, so their earliest registry dates are not checkable this way.

“Made by” is each project’s own account of itself, linked on its page. It was not checked against a second source: the build session could not reach Wikipedia.

The design

Each framework is drawn as a small scene of the idea that sets it apart, in its own colour: a component tree that re-renders one branch (React), one signal reaching the exact places that read it (Solid), a compiler that runs once (Svelte), a sea of plain HTML with a few live islands (Astro), a request and a swapped fragment (htmx), and so on. The scenes are decorative; the words on the card say the same thing. The home page holds all twelve on one screen, grouped by kind, and every other page is a plain reference page.

It was directed with the DADA design skill. The first version of this site (a four-framework overview) is kept on the original-overview branch of this repository, and an earlier collage-style version, graded C by the author as “too unappealing”, is in the frameworks repository. The light and dark toggle and the pros and cons form come from the first version.

Each framework page links the project’s documentation and a Wikipedia article to read further. Frameworks change fast: check the documentation for the current version.
