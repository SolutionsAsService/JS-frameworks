hypermedia library

htmx

Ask the server for HTML and put it where you say, with attributes.

  • Kindhypermedia library
  • Made byCarson Gross
  • Since2020 (1.0)
  • Written inHTML attributes; any server language
  • Checked on npm1.0.0 on 2020-11-24

At a glance

Pros

No build, no client state to keep in sync. Works with any backend language.

Cons

Every interaction that changes state needs a server round trip. Rich client-only interactions (drag, offline, optimistic UI) need other tools.

What it is

htmx extends HTML so that any element can make a request and any response can replace part of the page. hx-post says which request to make, and hx-target and hx-swap say where the answer goes.

It succeeds intercooler.js, by the same author, and is built on the idea of hypermedia: the server returns HTML, not JSON, and the page changes by exchanging HTML.

How it works

  1. Add hx-* attributes to HTML
  2. One small script ships
  3. An event sends a request to the server
  4. The server answers with an HTML fragment, which htmx swaps into the page

The server holds the state and does the rendering, in whatever language it already uses. The browser holds the script and the markup. A click sends a request, the server replies with a fragment of HTML, and htmx swaps it in.

It needs no build step and no client-side component model, which is also what it gives up: the page cannot respond to a click without a round trip, unless other script is written.

Overlaps and differences

Overlaps with

  • Astro: Both favour mostly-HTML pages with a little interactivity.
  • Lit: Both add behaviour to HTML without a virtual DOM.

Differs from

  • React: React moves the UI into the browser as code; htmx keeps it on the server as HTML.
  • Qwik: Qwik renders on the server and resumes on the client; htmx stays on the server for every change.

What it is good at, and what it costs

Good at

  • No build, no client state to keep in sync
  • Works with any backend language
  • Small single script

Costs

  • Every interaction that changes state needs a server round trip
  • Rich client-only interactions (drag, offline, optimistic UI) need other tools
  • State and logic live on the server, so the server must be there
