How to read the cards

A framework is an answer to one question: how does a change in your data become a change on the screen?

The answers differ in where the HTML is made (the browser, a server, at build time), in how a change is found (compare two trees, track what was read, compile it away, ask the server), and in how much is in the box (a view library, or routing, forms and servers as well). Each card’s drawing is its own answer, and its row says which kind it is: library, framework, meta-framework (a framework built on a library) or a different model.

The number on each card is a measurement, not a ranking. It is the JavaScript files for a page with one button, built the way each framework recommends (script written inside the HTML page is not counted), and the frameworks that make their HTML on the server (marked “server HTML”) also send a page that already has the count in it. A framework’s cost for a real app depends on the app, and a counter says nothing about how that cost grows. What was measured and what was not.

The star marks the 3 frameworks that the public repositories of the author’s GitHub profile (SolutionsAsService) use. See which.

The twelve were chosen by the author, not by a ranking: the three used in those repositories (React, Next.js, Lit), three the author wanted covered (Angular, Vue, Svelte), and six more that are widely used or take a different road (Nuxt, Solid, Preact, Qwik, Astro, htmx). Pros and cons at a glance

The first version of this site was a short overview of React, Vue, Angular and Svelte with a pros and cons line each; those four lines are kept below as they were written, and the other eight follow the same form.

FrameworkProsCons
ReactLarge community, reusable components, robust ecosystem.Requires JSX and build tooling, steeper learning curve.
PreactReact’s model at a fraction of the download (see the measured figure). Most React libraries work through the compatibility layer.Not every React feature or library behaves identically. Smaller team and ecosystem than React.
SolidUpdates are targeted by construction. React-like syntax eases the move for React developers.A far smaller ecosystem than React’s. Habits from React (destructuring props, conditionals in JSX) can silently break reactivity.
LitComponents that work everywhere. Very small library on top of platform features.No router, store or full-stack story of its own. Shadow DOM makes global styling and some form handling harder.
VueEasy to learn, flexible, and highly approachable.Smaller ecosystem compared to React, less corporate backing.
AngularComprehensive framework, built-in TypeScript support, two-way data binding.Verbose syntax, steep learning curve, heavy structure.
SvelteCompiles to efficient vanilla JavaScript, minimal runtime overhead, simple syntax.Smaller community, less mature tooling and ecosystem.
QwikBuilt so that start-up cost need not grow with the app (not shown by a counter, which is too small). Code for a feature loads when used.Developers must learn the $ rules about what can be serialised. A small ecosystem and few libraries built for it.
Next.jsOne tool for pages, routes, rendering modes and deployment. Search-friendly HTML from the first response.It inherits React’s runtime and adds its own (see the measured figure). Several rendering modes and caching layers must be understood to predict behaviour.
NuxtA full-stack Vue app with little configuration. Rendering mode chosen per route.Convention and auto-imports hide code paths that a plain Vue app shows. Adds a server runtime and build step to Vue’s own.
AstroContent pages with no JavaScript cost. Use the UI library you already know, or several.Not made for highly interactive, app-like pages. State shared between islands needs extra care.
htmxNo build, no client state to keep in sync. Works with any backend language.Every interaction that changes state needs a server round trip. Rich client-only interactions (drag, offline, optimistic UI) need other tools.
